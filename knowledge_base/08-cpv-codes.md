# CPV codes — Common Procurement Vocabulary

`[TEAM DECISION]` CPV is our shared category system for normalising demand across sources.

## Structure `[OWN KNOWLEDGE]`
- CPV 2008 (Regulation (EC) No 213/2008). Code = 8 digits + check digit, e.g. `35300000-0`.
- Hierarchy from the left: 2 digits **division** → 3 **group** → 4 **class** →
  5 **category** → digits 6–8 more detail. Trailing zeros mark the level.
  e.g. `35000000` → `35300000` → `35330000` → `35331000`.
- There is also a supplementary vocabulary (attributes like material or use). We ignore it for now.

## Pitfalls `[VERIFIED 2026-10-30]` unless marked
1. **35000000 is broader than defence**: "Security, fire-fighting, police and defence
   equipment". A query on 35000000 returned fire-fighting vehicles. Use the 353–358 roots.
2. **TED CPV search includes children**: `classification-cpv=35300000` matched notices coded
   35331000 and 35332200. Good — but remember you are querying a subtree.
3. **Defence buyers often use generic CPVs**: e.g. a Romanian MoD award under 44211100
   (modular and portable buildings), Polish army security services under generic security CPVs.
   CPV alone misses much defence demand → also filter by `legal-basis=32009L0081` and by
   buyer (MoD, AU, BAAINBw, DGA…).
4. **CPV ≠ capability**. CPV describes *what is bought*, not *what a firm can do*. A CNC
   machining shop can serve dozens of CPVs; "precision machining" has no CPV. We need a
   separate capability taxonomy and a many-to-many map CPV ↔ capability, learned from award
   history (which winners win which CPVs) plus embeddings. See
   [10-ontology-data-model.md](10-ontology-data-model.md). `[HYPOTHESIS]`
5. Notices repeat CPVs per lot — deduplicate.
6. **`35341100` "Gunmetal pipe fittings"** sits under *Parts of firearms* but is used for bronze
   plumbing (water-pipe tenders show up). Exclude it when it is a notice's only focus code.
   `[VERIFIED 2026-10-30]` — see [21-focus-scope.md](21-focus-scope.md).
